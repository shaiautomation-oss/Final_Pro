# הבדיקות שביצעתי

תשע בדיקות קבלה שמכסות את כל עשרת התהליכים. כולן בוצעו מול נתונים אמיתיים
במערכת החיה, והתוצאות שלהן מתועדות כאן.

---

## 1 · טעינת המאגר הווקטורי — WF6 · WF7

הרצתי ידנית את WF6 ואחריו את WF7.

**התוצאה:** 12 מסמכי המדיניות נחתכו ל-**68 קטעים**, וקובץ המוצרים נטען
כ-**34 רשומות**. שתי ההרצות הסתיימו בהצלחה.

---

## 2 · שליפת מדיניות — WF5 + WF6

שאלתי את בוט הלקוחות: `מה מדיניות ההחזרות?`

**התשובה כללה:** זכות ביטול של **14 ימים** בעסקת מכר מרחוק · ההבחנה בין
החזרה עקב פגם לבין החזרה עקב חרטה · פריטים שאינם ניתנים להחזרה בחרטה —
תוכנה שנפתחה, אוזניות תוך-אוזן וכרטיסי מתנה.

כל הפרטים תואמים למסמך `data/policies/01-returns-and-refunds.md`. הסוכן שלף
שלושה חלקים שונים מהמסמך והרכיב מהם תשובה אחת.

---

## 3 · שליפת מוצרים — WF5 + WF7

שאלתי: `יש לכם אוזניות אלחוטיות?`

**התשובה החזירה שלושה מוצרים אמיתיים מהקטלוג:**

| מוצר | מחיר | פרטים שצוינו |
|---|---|---|
| אוזניות אלחוטיות TY-200 | 349 ₪ | ANC · בלוטות' 5.3 · 30 שעות |
| אוזניות תוך-אוזן TY-Buds Pro | 289 ₪ | ANC · IPX5 · 32 שעות עם הנרתיק |
| אוזניות גיימינג TY-Gamer H7 | 429 ₪ | מיקרופון נשלף · 7.1 · דונגל 2.4GHz |

כל השמות, המחירים והמפרטים תואמים ל-`data/products/products.csv`.

## 4 · גבולות הסוכן

זו הבדיקה המשמעותית ביותר מבחינת סיכון עסקי. שלחתי לבוט הלקוחות:
`האם אפשר לקבל הנחה של 50%`

**התשובה:** *"אין לי אפשרות לאשר הנחות חריגות. אני ממליץ לפנות לשירות
הלקוחות, ואעביר את הבקשה שלך לבדיקה."*

הסוכן לא אישר הנחה, לא המציא תנאי, והפנה לגורם אנושי — בדיוק כפי שהוגדר
בהנחיית המערכת.

---

## 5 · סוכן המנהל ובקרת ההרשאות — WF9

**עם נתונים במערכת:** שאלתי `מה ההכנסות?` וקיבלתי:

> *"יש לך חשבונית אחת במערכת עם הכנסות של 1,180 ש"ח, שכוללות מע"מ. יש לך גם
> חשבונית אחת שטרם שולמה בסכום זהה. תובנה: כל ההכנסות שלך כרגע תלויות
> בחשבונית אחת שטרם שולמה."*

המספרים תואמים לטבלה במדויק, והתובנה נובעת מהם.

**כשהטבלה הייתה ריקה:** הסוכן ענה `ההכנסות הכוללות הן 0 ש"ח, ואין חשבוניות
במערכת` — בלי להמציא נתון.

**בקרת הרשאות:** פנייה מחשבון שאינו הבעלים קיבלה
*"הבוט הזה מיועד לבעל העסק בלבד"* — בלי שום נתון.

## 6 · מחזור החשבונית המלא — WF1 + WF8

יצרתי ב-`Invoices` רשומה עם שני שדות בלבד: `CustomerId = CUST-0001`
ו-`Amount = 1000`.

**מה שהתמלא אוטומטית:**

| שדה | ערך | מי כתב |
|---|---|---|
| `VatAmount` | 180 | WF1 — מע"מ 18% |
| `Total` | 1180 | WF1 |
| `InvoiceNumber` | INV-2026-0002 | WF1 — מספור רץ |
| `Status` | Ready → Issued | WF1 → WF8 |
| `PdfUrl` | קישור לגוגל דרייב | WF8 |

המסמך שהופק הוא HTML בעברית RTL עם `1,000.00` · `180.00` · `1,180.00`
והכיתוב "מע\"מ 18%", ונשמר בדרייב תחת `INV-2026-0002.html`.

## 7 · קליטת ליד וסינון כפילויות — WF3

שלחתי בקשת POST לכתובת ה-Webhook:

```json
{ "name": "שי ביטון", "email": "lead@example.com", "company": "לוי טכנולוגיות" }
```

**תשובה ראשונה:**
```json
{ "ok": true, "status": "created", "recordId": "rec...", "message": "הליד נוצר בהצלחה" }
```

**אותה בקשה בדיוק, בשנייה:**
```json
{ "ok": true, "status": "duplicate", "existing": 1, "message": "הליד כבר קיים במערכת" }
```

ב-Airtable נותרה **רשומה אחת בלבד** — סינון הכפילויות פועל.

הרצתי את WF4a על הליד שנקלט.

## 10 · ממשק האפליקציה — WF13

ארבע בדיקות מול ה-Webhook:

| בקשה | תוצאה |
|---|---|
| `{"action":"list","table":"Invoices","limit":10}` | `{ok:true, records:[...]}` — הרשומה חזרה שטוחה ומוכנה לתצוגה |
| `{"action":"create","table":"Tasks","payload":{...}}` | `{ok:true, action:"create", record:{...}}` + רשומה חדשה ב-`Tasks` |
| `{"action":"chat","message":"מה מדיניות האחריות?"}` | `{ok:true, reply:"..."}` — תשובה תואמת ל-`02-warranty.md` |
| `{"action":"banana"}` | HTTP 400 + `{ok:false, error:"פעולה לא מוכרת: banana", allowed:[...]}` |

לבסוף, אפליקציית Base44 חוברה לאותה כתובת ומציגה את הנתונים מכל ארבע
הטבלאות.
